## What it is

`mujoco-wasm-forge` is a **reproducible MuJoCo→WebAssembly build pipeline** that treats the exported ABI as a first-class, auditable contract.
It produces stable runtime artifacts (`mujoco.js` / `mujoco.wasm`) plus ABI audit outputs under `dist/<ver>/abi/`.

It is designed to support **Simulate-style** web apps (via `mujoco-wasm-play`) while keeping upgrades safe: when upstream MuJoCo changes, you can see *exactly* what moved in headers, wrappers, exports, and implementations.
Docs (Sphinx/RTD) live under `docs/`; bench methodology and reference snapshots are in `docs/en/bench.md`.

## Quickstart

```bash
python forge_cli.py build --version 3.5.0 --with-checks
```

Artifacts:
- `dist/3.5.0/mujoco.js`, `dist/3.5.0/mujoco.wasm`
- `dist/3.5.0/abi/exports.lst` and other ABI artifacts
- optional pthreads runtime under `dist/3.5.0/pthreads/`

## Why forge

- **Controlled exports**: `dist/<ver>/abi/exports.lst` is the single source of truth (fed to `-sEXPORTED_FUNCTIONS=@...`).
- **Auditable ABI**: `dist/<ver>/abi/` captures introspect + wrapper + `nm` symbol views, so diffs are explainable and reviewable.
- **Rule-based generation**: interfaces/exports are enforced by rules/gates ("change rules -> regenerate -> gate"), making upgrades auditable and regression-friendly.
- **Variants without breaking names**: `dist/<ver>/mujoco.{js,wasm}` (single) and `dist/<ver>/pthreads/mujoco.{js,wasm}` (pthreads).
- **Plugins included by default** (e.g. `mujoco.sensor.touch_grid`), so Simulate workloads do not silently regress.
- **Quality gates**: smoke + mesh-smoke + export/ABI checks are runnable locally and in CI.
- **Performance is measurable**: the bench suite thread-matches against official embind and uses Simulate TTFS to validate that flexibility does not imply unacceptable regressions.

## Official embind and forge (positioning)

This is a practical "what you get" view. Methodology and reference snapshots are in `docs/en/bench.md`.

| Topic | Official embind (MuJoCo wasm/) | Forge |
| --- | --- | --- |
| Focus | Ergonomic embind JS API + standardized distribution | Controlled exports + auditable artifacts + variant-friendly dist |
| Export contract | Embind-generated JS API; no `exports.lst` artifact | Explicit `dist/<ver>/abi/exports.lst` drives `-sEXPORTED_FUNCTIONS` |
| ABI audit artifacts | Not provided as a bundle | `dist/<ver>/abi/*` (introspect, wrappers, `nm` views, reports) |
| Threading defaults (3.5.0) | `-pthread` + `PTHREAD_POOL_SIZE=navigator.hardwareConcurrency` | Single-thread artifacts remain first-class; pthreads is an opt-in variant (default pool: 4, configurable) |
| Plugin availability (touch_grid) | Missing in our 3.4.0/3.5.0 embind builds | Included by default |

## Workflow (high level)

- Entry point: `forge_cli.py` (`prepare → introspect → ABI → build → post-build checks`).
- Output: `dist/<ver>/mujoco.{js,wasm}` + `dist/<ver>/abi/*`.
- Optional pthreads runtime: `dist/<ver>/pthreads/` (shared ABI under `dist/<ver>/abi/`).

## Notes

- Simulate-style web demo / downstream consumer: https://github.com/lshdlut/mujoco-wasm-play
- For pthreads builds (`python forge_cli.py build --version <ver> --pthreads`):
  - `MJWF_PTHREAD_POOL_SIZE` (integer >=1, default: 4) sets `-sPTHREAD_POOL_SIZE=<n>`.
  - `MJWF_PTHREADS_COMPILER_MAX_THREADS` (0 disables clamp; default follows `MJWF_PTHREAD_POOL_SIZE` for MuJoCo 3.5.0) caps MuJoCo's XML compiler thread pool.
